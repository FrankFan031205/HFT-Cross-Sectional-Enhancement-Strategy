# BacktestingModel

`BacktestingModel` is an execution-aware backtesting framework for high-frequency market making strategies on China A-share equities.

It evaluates fixed quote decisions generated by `MarketMakingModel`, simulates fills using raw trades and order book snapshots, applies A-share transaction costs, calculates markout PnL, and performs inventory-aware portfolio replay under realistic trading constraints such as no-short, T+1 sellable inventory, initial inventory pool, maximum position cap, and inventory-band controls.

---

## 1. Purpose

The purpose of this module is to separate signal quality from execution quality and inventory risk.

The full evaluation stack is:

```text
quote decision
    ↓
fill simulation
    ↓
transaction cost and markout PnL
    ↓
policy-level filtering
    ↓
inventory-aware execution overlay
    ↓
portfolio replay
    ↓
capital / exposure / drawdown analysis
```

This allows us to answer different research questions:

| Layer | Question |
|---|---|
| Touched-fill | If the market touches our quote, does the quote direction have alpha? |
| Queue-aware fill | Does the strategy still work after considering queue priority? |
| Policy filter | Which signal regions are worth executing? |
| Inventory constraint | Can the strategy satisfy A-share no-short and T+1 rules? |
| Portfolio replay | What are the capital usage, inventory drift, exposure, and drawdown? |

## 2. Current Final Baseline

The current recommended baseline is:

```text
Final Inventory-Aware Backtest Baseline
```

It is defined as:

```yaml
fill_model:
  mode: queue_aware_trade
  queue_ahead_multiplier: 0.05

policy:
  name: abs_top40
  type: abs_signal_quantile
  quantile: 0.60

inventory:
  initial_position_per_symbol: 5000
  max_position_per_symbol: 15000
  sell_floor_position: 3000
  buy_block_position: 9000
  tplus1: true
  allow_short: false

fee:
  mode: single_fill_side_specific
  commission_rate: 0.00005
  transfer_fee_rate: 0.00001
  handling_fee_rate: 0.0000341
  regulatory_fee_rate: 0.00002
  stamp_duty_rate: 0.0005
```

Interpretation:

```text
queue_ahead_multiplier = 0.05
    Assume only 5% of visible queue is effectively ahead of our order.

abs_top40
    Only accept trades with signal absolute value in the top 40%.

initial_position_per_symbol = 5000
    Each stock starts with 5000 shares of initial sellable inventory.

max_position_per_symbol = 15000
    Position in each stock cannot exceed 15000 shares.

sell_floor_position = 3000
    Do not sell if the resulting position would fall below 3000 shares.

buy_block_position = 9000
    Stop accepting additional BUY fills when inventory is already high.

tplus1 = true
    Shares bought today cannot be sold on the same day.

allow_short = false
    Short selling is not allowed.
```

## 6. Fill Simulation

### 6.1 Touched-fill

Touched-fill is the optimistic execution baseline.

For a BUY quote:

```text
If future active sell trades touch our bid price within quote TTL,
we assume the bid quote is filled.
```

For a SELL quote:

```text
If future active buy trades touch our ask price within quote TTL,
we assume the ask quote is filled.
```

Current quote lifecycle assumption:

```text
latency_ms = 0
quote_ttl_ms = 500
```

Order active window:

```text
[decision_time, decision_time + 500ms)
```

Touched-fill is useful for signal validation, but it is optimistic.

---

### 6.2 Queue-aware Fill

Queue-aware fill considers visible queue priority.

For a BUY quote:

```text
queue_ahead = visible bid volume at quote price
opposite active sell trades consume queue_ahead
our order fills only after queue_ahead is consumed
```

For a SELL quote:

```text
queue_ahead = visible ask volume at quote price
opposite active buy trades consume queue_ahead
our order fills only after queue_ahead is consumed
```

The current effective queue assumption is:

```yaml
queue_ahead_multiplier: 0.05
```

Meaning:

```text
effective_queue_ahead = visible_queue * 0.05
```

This parameter controls execution conservativeness:

```text
0.0 = touched-fill / front-of-queue assumption
1.0 = fully behind visible queue
```

## 7. Transaction Cost Model

The current A-share cost model is side-specific and applied once per fill.

```yaml
commission_rate:      0.00005
transfer_fee_rate:    0.00001
handling_fee_rate:    0.0000341
regulatory_fee_rate:  0.00002
stamp_duty_rate:      0.0005
```

BUY cost:

```text
commission + transfer + handling + regulatory
```

SELL cost:

```text
commission + transfer + handling + regulatory + stamp duty
```

---

## 8. Markout PnL

The basic PnL layer uses 60-second markout.

For BUY fills:

```text
gross_pnl = (future_mid - fill_price) * fill_qty
```

For SELL fills:

```text
gross_pnl = (fill_price - future_mid) * fill_qty
```

Net PnL:

```text
net_pnl = gross_pnl - fee
```

Return on notional:

```text
net_pnl_bps = net_pnl / notional * 10000
```

Important distinction:

```text
markout PnL measures fill-level signal and execution quality.
portfolio replay PnL measures strategy-level inventory-aware performance.
```

## 9. Policy Filter Layer

Policy filters are applied only inside `BacktestingModel`.

They do not modify the original quote file.

Supported policy examples:

```text
all
abs_signal_quantile
buy_only
sell_only
directional threshold policies
risk_state filters
```

Current final policy:

```yaml
policy:
  name: abs_top40
  type: abs_signal_quantile
  quantile: 0.60
```

This keeps trades where:

```text
abs(signal) >= 60th percentile
```

In other words:

```text
keep top 40% strongest absolute signal trades
```

Why this policy:

```text
Weak signals diluted performance.
Strong-signal filters improved turnover-adjusted return and capital efficiency.
```

## 10. Inventory-aware Overlay

The inventory-aware overlay simulates realistic A-share execution constraints.

It enforces:

```text
no naked short selling
T+1 sellable inventory
initial inventory pool
max position cap
high-inventory BUY block
low-inventory SELL block
```

Current final parameters:

```yaml
initial_position_per_symbol: 5000
max_position_per_symbol: 15000
sell_floor_position: 3000
buy_block_position: 9000
tplus1: true
allow_short: false
```

Logic:

```text
BUY:
    reject if position + qty > max_position
    reject if position >= buy_block_position

SELL:
    reject if sellable_inventory < qty
    reject if position - qty < sell_floor_position
```

At the beginning of a new trading day:

```text
sellable_inventory = max(position, 0)
```

This simulates A-share T+1 sellable inventory.

## 11. Portfolio Replay

Portfolio replay converts accepted trades into position / cash / equity paths.

For BUY:

```text
position += qty
cash -= fill_price * qty + fee
```

For SELL:

```text
position -= qty
cash += fill_price * qty - fee
```

Equity:

```text
equity = cash + inventory_value
```

Inventory value is marked using the available mark price in the trade file.

Portfolio metrics:

```text
total_pnl
total_turnover
pnl_bps_on_turnover
max_gross_exposure
max_abs_net_exposure
max_drawdown
return_on_max_gross_exposure
num_long_symbols_end
num_short_symbols_end
num_short_events
num_short_violations_if_no_short
```

## 15. Key Metrics

### Total Notional / Turnover

```text
total_turnover = sum(fill_price * fill_qty)
```

This is not capital. It is total traded notional.

---

### PnL bps on Turnover

```text
pnl_bps_on_turnover = total_pnl / total_turnover * 10000
```

Measures trading efficiency.

---

### Max Gross Exposure

```text
gross_exposure = sum(abs(position_i * price_i))
```

Measures maximum inventory capital usage.

---

### Return on Max Gross Exposure

```text
return_on_max_gross_exposure = total_pnl / max_gross_exposure
```

Measures capital efficiency.

---

### Max Drawdown

```text
max_drawdown = min(equity_t - running_max_equity_t)
```

Negative number. More negative means worse drawdown.

---

### Short Events

```text
num_short_events
num_short_violations_if_no_short
```

For A-share realistic backtest, these should be zero.

## 18. Current Limitations

This is a research-grade execution-aware backtesting framework, not a production exchange simulator.

Current limitations:

```text
1. latency-aware order arrival is not fully modeled
2. order lifecycle is simplified
3. cancel-adjusted queue movement is not yet included
4. partial fill and order size sensitivity can be improved
5. end-of-day liquidation / overnight inventory handling is not fully modeled
6. capital allocation is approximated by max gross exposure
7. quote cancel / amend latency is not explicitly simulated
```

Recommended future extensions:

```text
B6: latency-aware fill simulation
B7: arrival-time snapshot queue estimation
B8: cancel-adjusted queue model
B9: order lifecycle with keep / cancel / amend
B10: end-of-day de-risking and liquidation model
```
